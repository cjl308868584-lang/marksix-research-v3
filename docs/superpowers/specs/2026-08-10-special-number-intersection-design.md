# 特码规律号码交集汇总设计

## 目标

在独立的近30期规律页面中，仅当用户选择“特码规律”时，增加01–49的规律交集汇总。它把已冻结的特码生肖、尾数、波色、头数规律投影到具体号码，展示研究分最高的前15个号码，并公开每个号码由哪些结果B与多少条条件策略支持。

## 边界

- 条件A仍然读取当期6+1特征。
- 结果B必须是下一期的特码分类结果。
- 仅使用当前目标期已经冻结、当前分类筛选范围内的特码规律。
- 不使用6+1覆盖规律，不生成新的条件规律，不改变正式策略概率。
- 号码排名是“规律交集研究分”，不是01–49的真实中奖概率。

## 汇总方法

1. 将每条特码规律的结果B映射到01–49：生肖按目标期开奖时间映射，尾数按个位数，波色按固定波色表，头数按十位区间。
2. 单条规律贡献使用贝叶斯收缩后的相对提升，并结合样本可靠度 `support / (support + 10)`；贡献设置上限，避免小样本100%命中支配排名。
3. 同一结果B的多条规律先合并为一个结果证据，再投影到号码，避免把高度相关策略当作完全独立证据重复放大。
4. 每个号码的研究分为其命中的不同结果证据贡献之和。排序依次为研究分、支持结果数、支持策略数、号码升序。
5. 最多展示前15名；每项展示号码、研究分、支持结果标签（例如 `0头`、`蓝波`）、策略数，以及各标签累计历史命中/失败。

## 页面交互

- 模块仅在“特码规律”范围显示，位置在“结果B支持汇总”之后、扫描漏斗之前。
- 每个号码以醒目的球号展示，支持结果标签使用黄色字体。
- 点击号码卡片，使用该号码对应的结果B集合筛选下方策略；再次点击取消筛选。
- 原有单个结果B卡片筛选仍然保留，两种筛选互斥，切换彩种、范围或分类时清空。
- 手机端使用单列/双列自适应卡片，无横向溢出。

## 接口与测试

- 纯函数负责号码映射、去相关汇总、排序和前15截断。
- API在 `scope=special` 时返回 `specialNumberConsensus`；其他范围返回空数组。
- API增加可选 `number=1..49` 参数，用于筛选下方所有支持该号码的原始规律。
- 测试覆盖波色示例（蓝波包含03、04、09）、多分类交集、去重、排名、范围隔离、号码筛选与页面文案。
