# 近30期条件规律双结果域与独立页面设计

## 目标

把近30期条件规律建设成独立研究页面，不再与“下一期策略”和“逐期复盘”组成同一页面导航。规律统一研究：当本期条件 A 在6+1中成立时，下一期结果 B 的概率是否高于 B 自身随机基准。

页面提供两个互不混算的结果域：

- `6+1覆盖规律`：结果 B 只研究生肖和尾数在下一期6+1中是否至少出现一次。
- `特码规律`：条件 A 仍来自本期6+1，结果 B 只检查下一期的特码；研究生肖、尾数、波色和头数。

系统不预测01–49具体号码。

## 1. 独立页面与入口

- `/patterns` 保持为独立页面。
- 首页保留“近30期条件规律”直达入口。
- `/patterns` 删除“下一期策略 / 近30期规律 / 逐期复盘”的共用页签，只保留返回开奖首页的入口。
- “下一期策略”和“逐期复盘”继续保留原有页面与互相跳转，但不再把近30期规律表现成同一研究流程中的页签。
- 旧地址 `/research/patterns` 继续重定向到 `/patterns`，避免历史链接失效。

## 2. 条件 A 的统一口径

两种结果域都使用相同的条件 A。条件 A 只读取当期完整6+1：

- 生肖：本期6+1是否至少出现一次指定生肖。
- 尾数：本期6+1是否至少出现一次指定尾数。
- 波色：本期6+1是否达到规则要求的指定波色数量。
- 头数：本期6+1是否达到规则要求的指定头数数量。

条件 A 可以是单条件或两个条件的交集。条件只使用当时已知的开奖，不得引用下一期结果或未来数据。

## 3. 6+1覆盖规律

`6+1覆盖规律`的结果 B 仅包含：

- 生肖：下一期6+1至少出现一次指定生肖。
- 尾数：下一期6+1至少出现一次指定尾数。

明确排除：

- 波色结果 B。
- 头数结果 B。
- 具体号码结果 B。

随机基准按7球无放回覆盖概率精确计算。生肖和尾数所含号码数量不同，因此必须按该结果实际包含的号码数计算，不能统一写成固定百分比。

## 4. 特码规律

`特码规律`的条件 A 仍然是当期6+1，结果 B 只检查下一期的特码，包含：

- 生肖：下一期的特码属于指定生肖。
- 尾数：下一期的特码属于指定尾数。
- 波色：下一期的特码属于指定波色。
- 头数：下一期的特码属于指定头数。

“特码全部要有”在本版本中明确表示以上四种分类全部生成，不包含01–49具体号码预测。

随机基准按单个特码计算：该分类包含的号码数除以49。命中结算只能读取 `draw.special`，不能读取正码或整期开奖覆盖。

## 5. 数据隔离与版本

规则引擎升级为 `conditional-patterns-v3`，并为每条结果事件保存范围：

- `coverage_6_plus_1`
- `special`

事件ID必须包含结果范围，避免同名生肖或尾数在两个结果域中发生冲突。旧 `conditional-patterns-v2` 冻结规律不得作为v3账本读取或结算。

每期开奖核验后，系统使用最新30期重新扫描两套结果域。新增一期时移除窗口最早一期，避免遗漏和重复。页面读取只展示已冻结结果，不触发扫描或写入。

## 6. 页面展示与切换

页面顶部提供局部结果域切换：

- `6+1覆盖规律`
- `特码规律`

它只是独立规律页内部的研究口径切换，不链接“下一期策略”或“逐期复盘”。切换结果域时清除已选分类、结果和分页状态。

分类按钮随结果域变化：

- 6+1覆盖规律：全部、生肖、尾数。
- 特码规律：全部、生肖、尾数、波色、头数。

统计、汇总、扫描漏斗和详细规律全部只计算当前结果域，两个结果域不得合计成一个总数。

## 7. 汇总排序与点击筛选

“结果 B 支持汇总”按汇总历史命中率从高到低排序。

并列时依次按：

1. 历史触发次数较多者优先。
2. 支持策略数量较多者优先。
3. 高于随机基准的百分点较高者优先。
4. 结果名称排序，保证结果稳定。

每个汇总结果改为可点击按钮：

- 点击“牛”，下方只显示结果 B 为牛的规律。
- 点击“7尾”，下方只显示结果 B 为7尾的规律。
- 再次点击同一结果取消筛选。
- 点击另一个结果立即切换筛选。
- 切换彩种、结果域或分类时清除已选结果。
- 选择结果后分页回到第1页。

API增加可选 `scope` 和 `result` 参数。处理顺序固定为：

1. 按彩种和结果域读取冻结账本。
2. 按当前结果域允许的分类过滤。
3. 用第2步的全部规律生成完整汇总。
4. 再按 `result eventId` 过滤下方逐条规律。
5. 最后分页。

因此点击结果只影响下方策略列表，顶部当前结果域的完整汇总保持可见。

## 8. 结果文字样式

结果统一使用短标签：

- `牛`
- `7尾`
- `红波`
- `4头`

只把结果文字本身改为醒目的黄色字体，不改变卡片背景、边框或其他数据颜色。逐条规律保留完整句子说明，例如“下一期6+1至少出现一次牛”或“下一期的特码为红波”。

## 9. 空状态与错误处理

- 新版v3冻结账本尚未生成时，页面显示“等待下一次已核验任务完成重扫”，不回退展示旧口径。
- 不支持的 `scope`、分类或 `result` 参数返回400。
- 合法但当前无匹配结果时返回空列表和零分页，当前结果域的顶部汇总仍正常显示。
- 生成或写入失败时保留上一份v3冻结结果，不写入半套结果域。

## 10. 验收标准

- `/patterns` 不再显示下一期策略与逐期复盘的共用页签，首页仍可直达。
- 页面可切换6+1覆盖规律和特码规律，统计数据不混算。
- 两套规律的条件 A 都只读取当期6+1。
- 6+1结果 B 只有生肖和尾数，并按7球覆盖概率计算基准。
- 特码结果 B 包含生肖、尾数、波色和头数，只读取特码并按单球概率计算基准。
- API和页面不生成或展示具体号码预测。
- 汇总严格按命中率降序，并按约定规则处理并列。
- 点击任一汇总结果后，下方只显示该结果的策略；再次点击恢复全部。
- 顶部汇总不会因结果筛选而缩成一个结果。
- `牛`、`7尾`、`红波`、`4头`等短结果仅字体变黄。
- 最新30期滚动扫描不会遗漏、重复或混入第31期。
- 360px手机页面无横向溢出。
- 下一期策略与逐期复盘功能无回归。
