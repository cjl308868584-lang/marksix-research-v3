# 近30期规律结果口径、排序与筛选设计

## 目标

修正近30期条件规律页面中波色和头数的结果口径，并增强结果汇总的排序、点击筛选和视觉辨识度。下一期策略与逐期复盘不改动。

## 1. 条件 A 与结果 B 的统计口径

条件 A 保持现有定义：

- 生肖：本期6+1是否至少出现一次指定生肖。
- 尾数：本期6+1是否至少出现一次指定尾数。
- 波色：本期6+1是否达到当前规则要求的指定波色数量。
- 头数：本期6+1是否达到当前规则要求的指定头数数量。

结果 B 改为：

- 生肖：下一期6+1至少出现一次指定生肖。
- 尾数：下一期6+1至少出现一次指定尾数。
- 波色：下一期特码属于指定波色。
- 头数：下一期特码属于指定头数。

因此，波色和头数允许使用6+1结构作为条件 A，但命中结算只检查下一期特码。系统必须分别生成“条件事件”和“结果事件”，不能再让同一事件定义同时承担两个口径。

波色、头数结果 B 的随机基准按特码单球计算：

- 波色基准：该波色包含号码数 ÷ 49。
- 头数基准：该头数包含号码数 ÷ 49。

生肖、尾数结果 B 继续使用7球无放回覆盖概率。

规则引擎升级到 `conditional-patterns-v3`，事件ID加入范围标识，旧版6+1波色/头数结果不得作为新版账本读取或结算。

## 2. 汇总排序

“结果 B 支持汇总”按汇总历史命中率从高到低排序。

并列时依次按：

1. 历史触发次数较多者优先。
2. 支持策略数量较多者优先。
3. 高于随机基准的百分点较高者优先。
4. 结果名称排序，保证结果稳定。

页面继续同时展示随机基准、相对基准差和触发次数，避免只凭小样本100%命中率判断强弱。

## 3. 点击汇总筛选下方策略

每个结果 B 汇总卡片改为可点击按钮：

- 点击“牛”，下方只显示结果 B 为牛的规律。
- 点击“7尾”，下方只显示结果 B 为7尾的规律。
- 再次点击同一结果取消筛选。
- 点击另一个结果立即切换筛选。
- 切换彩种或分类时清除已选结果。
- 选择结果后分页回到第1页。

API增加可选 `result` 参数。处理顺序固定为：

1. 按彩种读取冻结账本。
2. 按生肖、尾数、波色或头数分类过滤。
3. 用第2步的全部规律生成完整汇总。
4. 再按 `result eventId` 过滤下方逐条规律。
5. 最后分页。

这样点击结果只影响下方策略列表，顶部完整汇总保持可见，方便继续选择其他结果。

## 4. 结果文字样式

结果统一使用短标签：

- `牛`
- `7尾`
- `红波`
- `4头`

只把结果文字本身改为醒目的黄色字体，不改变卡片背景、边框或其他数据颜色。

汇总卡片顶部显示黄色短结果；逐条规律的“下一期结果 B”区域也显示黄色短结果，并保留完整句子说明其口径，例如“下一期特码为红波”。

## 5. 数据、兼容与空状态

- 旧 `conditional-patterns-v2` 冻结规律不与v3混用。
- 新版规律仍使用最近30期已核验数据，每期开奖后重新扫描。
- 页面读取不触发扫描、训练、结算或写入。
- 若新版冻结账本尚未生成，页面显示“等待下一次已核验任务完成重扫”，不回退展示旧口径。
- 无效或不存在的 `result` 参数返回400；合法但当前无匹配结果时返回空列表和零分页，不影响顶部汇总。

## 6. 验收标准

- 波色条件 A 仍可描述6+1数量条件，但波色结果 B 只检查特码。
- 头数条件 A 仍可描述6+1数量条件，但头数结果 B 只检查特码。
- 波色与头数结果 B 使用单球理论基准。
- 生肖与尾数结果 B 仍使用6+1覆盖基准。
- 结果汇总严格按命中率降序，并按约定规则处理并列。
- 点击任一结果后，下方只显示该结果的策略；再次点击恢复全部。
- 顶部汇总不会因结果筛选而缩成一个结果。
- `牛`、`7尾`、`红波`、`4头`等短结果仅字体变黄。
- 360px手机页面无横向溢出。
- 下一期策略与逐期复盘页面无功能回归。
