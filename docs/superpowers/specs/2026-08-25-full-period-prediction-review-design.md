# 全量逐期预测复盘设计

## 目标

让用户可以永久复盘每一期开奖前冻结的预测，并在开奖后看到明确的命中、未命中或待开奖状态。功能覆盖：

1. 近30期规律页的五项购买参考；
2. 近30期规律页两个结果范围的“结果 B 支持汇总”；
3. 特码范围的“特码号码交集前15”；
4. 逐期学习中心每一期正式五项结算。

旧的“逐期汇总结算”面板整块移除，不能与新复盘并存。

## 用户体验

### 近30期规律页

在当前预测区域之后增加“逐期预测复盘”。默认列出最新20期，按期号倒序排列；点击一期后才加载该期详细内容。用户可以不断点击“加载更早期数”，直到现有账本的最早一期。

每一期详情包含三个区域：

- 五项购买参考：单肖、单尾、二连肖、三连肖、特码号码各一项；显示冻结概率、赔率、EV、理由及命中状态。
- 结果 B 支持汇总：分别保留“6+1覆盖”和“特码”两个冻结结果集合；每个结果显示冻结时的策略数、历史命中/失败和本期实际命中状态。
- 特码号码交集前15：保留冻结排名、号码、研究分、证据标签与历史统计；开奖后最多一个号码标记命中，其余标记未命中。

期号标题同时显示冻结时间、结算状态、实际6+1号码和特码。尚未开奖的项目统一显示“待开奖”，不制造历史成绩。

### 逐期学习中心

将“最近一期逐项结算”改成“逐期五项结算”。每一期都是可展开的独立卡片，显示五个正式槽位的预测、冻结概率、精确基线、命中状态、实际特码和本期 Brier skill。默认20期，并可持续加载更早期数。

## 数据设计

现有不可变表继续作为审计源：`rolling_pattern_runs`、`rolling_pattern_signals`、`rolling_pattern_scores`、`rolling_pattern_consensus_ledger` 和 `rolling_pattern_consensus_scores`。新增两个紧凑读模型，避免每次查看历史都重复扫描大量规则：

### `rolling_pattern_review_snapshots`

每个 `run_id` 一行，且 `(game, target_issue)` 唯一。

- `run_id`
- `game`
- `target_issue`
- `snapshot_json`
- `frozen_at`

`snapshot_json` 保存：五项原始30期购买参考、两个范围的完整汇总、结果 B 的可结算事件定义、特码交集前15及其证据。写入后不可更新。

### `rolling_pattern_review_scores`

每个 `run_id` 一行，且 `(game, target_issue)` 唯一。

- `run_id`
- `game`
- `target_issue`
- `actual_json`
- `score_json`
- `scored_at`

`score_json` 保存三个区域的逐项命中结果；`actual_json` 保存实际6+1号码和特码。使用 `INSERT OR IGNORE`，同一期重复任务不能改写首次结算。

## 写入与结算流程

1. 30期规律运行冻结后，先保存原始信号和产品，再由同一批冻结数据生成复盘快照。
2. 已核验开奖到达时，用快照中的冻结事件和产品逐项结算，追加唯一的复盘结算行。
3. 每次签名后台任务检查缺少快照的旧运行，最多分批补齐50期；随后为已有已核验开奖的快照补齐结算。
4. 公共读取接口永远只读，不触发冻结、结算或学习。
5. 如果旧期快照尚未完成后台补齐，详情接口可以从现有不可变账本即时还原该期，保证历史可见；即时还原不写数据库。

## 分页与额度控制

- 历史索引查询一次只读取21行，用第21行判断是否还有更早记录。
- 详情只在用户展开某一期时读取一条紧凑快照和一条结算记录。
- 默认每页20期，使用期号游标，不使用随历史增长越来越昂贵的 OFFSET。
- 逐期学习中心同样采用20期游标分页；数据库继续永久保存全部期数，页面不一次加载全部。

## 不可变与准确性规则

- 任何预测必须早于该期开奖时间冻结。
- 同彩种同目标期只接受最早的有效快照和首次有效结算。
- 历史页面必须显示冻结值，不能用当前30期窗口重新计算旧期结果。
- 原始30期购买参考不得读取逐期学习中心的学习后推荐。
- 结果 B 同一事件的实际状态必须一致；不一致时该期详情返回不可用，不能任选一个结果。
- 只有跨来源核验的开奖可以结算。
- 无法完整还原的旧期明确标记“历史数据不完整”，不能补造预测。

## API

新增只读接口 `GET /api/research/patterns/reviews`：

- 索引：`game`、`limit`、可选 `before`，返回期号、冻结时间、是否已结算和下一游标。
- 详情：`game`、`issue`，返回完整快照与结算；优先读取紧凑快照，缺失时从不可变源账本还原。
- 所有响应使用 `Cache-Control: private, no-store`，拒绝未知参数和非法期号。

扩展 `GET /api/learning/reviews`：

- 支持可选 `before` 游标；返回 `nextCursor`。
- 继续只返回最高 committed v2 修订的完整五项正式分数。

## 验证范围

- 纯函数测试：快照内容、结果 B 结算、特码前15结算、待开奖状态。
- 存储测试：首次冻结不可变、重复写入幂等、旧期补齐、游标分页。
- API测试：参数校验、无缓存、历史索引、单期详情、学习复盘分页。
- 页面测试：旧面板文案消失；新复盘标题、三个区域和学习历史列表存在。
- 完整验证：TypeScript、核心测试、Python研究测试、生产构建、部署配置测试和服务端渲染测试。
