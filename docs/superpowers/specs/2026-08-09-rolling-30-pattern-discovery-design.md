# 近30期规律发现页面设计

## 目标

新增一个独立的“近30期规律”页面，用最新30期已核验开奖记录寻找当前已经触发、能够指向下一期、且历史命中率高于对应随机基准的近期规律。

该页面属于近期探索工具，不修改现有正式策略概率、模型权重、冠军挑战机制或已经冻结的预测账本。即使某条规律在30期内触发3次并命中2次，页面也可以展示其原始命中率 `2/3 = 66.7%`，但必须同时展示样本量、随机基准、收缩后概率和“小样本”标签，不能把原始命中率描述成已验证概率。

## 数据窗口与时间边界

- 每个彩种独立维护窗口；香港与新澳门不得混合数据。
- 每次扫描只读取目标期开奖前最新30期、且质量等级为 `official_verified` 或 `multi_source_consistent` 的开奖。
- 窗口少于30期、存在未解决冲突或最新一期尚未核验时，不生成新的当前结果。
- 新一期核验后，先结算上一期冻结信号，再加入新一期、删除最旧一期，重新生成完整30期窗口。
- 历史命中只能使用规律触发时已经可见的数据。窗口最后一个状态可用于判断下一期是否触发，但不能计入尚未开奖的历史命中。
- 时间固定为 `Asia/Shanghai`；扫描目标期、来源期、窗口首尾期和冻结时间必须完整保存。

## 事件口径

首版只研究分类覆盖或分类数量事件，不预测具体号码。

### 生肖

事件定义为“下一期6+1中指定生肖至少出现一次”。生肖号码集合必须按对应开奖日期计算。随机基准根据该生肖当年包含4个还是5个号码，使用7球无放回概率精确计算。

### 尾数

事件定义为“下一期6+1中指定尾数至少出现一次”。尾数包含4个或5个号码，随机基准按实际成员数量使用7球无放回概率计算。

### 波色

“某波至少出现一次”的基准过高，不具有筛选价值。首版事件定义为“下一期6+1中指定波色至少出现3个”，按红、蓝、绿波实际号码集合使用超几何分布计算基准。

### 头数

头数定义为：`0头=01–09`、`1头=10–19`、`2头=20–29`、`3头=30–39`、`4头=40–49`。事件定义为“下一期6+1中指定头数至少出现2个”，按各头实际号码数使用超几何分布计算基准。

## 首版规律模板

每个目标事件先转换为逐期二元状态：该期开奖是否满足事件。规则引擎只生成以下有限模板，避免30期数据上的无限组合爆炸。

1. **遗漏回补**：目标事件连续未出现 `1–5` 期后，预测下一期出现。
2. **连续延续**：目标事件连续出现 `1–3` 期后，预测下一期继续出现。
3. **二至四期状态转移**：最近 `2–4` 期的出现/未出现序列，预测下一期出现。
4. **固定滞后重现**：前 `2–5` 期的指定一期出现，且中间状态满足同一规范条件时，预测下一期出现。

首版不加入两个前置分类的交叉组合、具体号码、位置号码或LLM生成规则。后续扩展必须先证明不会让候选数量和假发现率失控。

## 展示资格与排序

规律只有同时满足以下条件才会出现在当前页面：

- 当前最新状态已经触发该规律，并能输出下一期的明确分类事件。
- 在当前30期窗口内有至少3个已经结算的历史触发样本。
- 原始历史命中率严格高于该事件的精确随机基准。
- 原始提升至少为5个百分点。
- 规则通过规范化去重，且不是恒真、未来引用或无法计算基准的规则。

允许 `3次触发、2次命中` 这类小样本结果展示。系统使用以精确随机基准为中心、强度为8个伪样本的 Beta-Binomial 收缩：

`收缩后概率 = (历史命中数 + 8 × 随机基准) / (历史触发数 + 8)`

收缩后概率只用于风险提示和排序，不会抹掉符合用户条件的原始规律。结果按以下顺序排列：收缩后提升、触发样本数、原始提升、最近触发时间。页面最多首屏展示20条，其余分页读取，不因页面上限删除冻结记录。

触发少于6次统一显示“小样本”；触发6–9次显示“有限样本”；10次及以上显示“近期重复”。所有结果统一标记为“待验证规律”，不得出现“已验证优势”字样。

## 去重与相关证据

每条规则转换为规范化JSON，字段固定为彩种、事件类型、事件值、窗口长度、规则家族、状态序列、预测方向和引擎版本，并生成稳定哈希。

- 相同规范化哈希只保存一次。
- 逻辑等价的遗漏状态与二元状态序列合并为同一规则，保留更容易理解的“遗漏回补”文案。
- 多条规则若指向同一个目标事件，可以在页面显示为不同触发逻辑，但必须标注相关规则数量，不能把它们当成独立证据相乘。
- 同一个运行ID重复执行时返回原结果，不增加触发次数、不重复结算、不重复生成页面记录。

## 自动扫描、冻结与复盘

规律扫描接入现有“开奖结果核验后”的逐期学习任务，顺序固定为：

1. 获取并完成多源核验。
2. 读取上一目标期冻结的规律信号。
3. 将实际6+1结果转换为生肖、尾数、波色数量和头数数量。
4. 逐条结算命中或失败，并保存实际结果。
5. 生成加入本期后的最新30期窗口及数据哈希。
6. 穷举有限模板，计算历史触发、命中和精确基准。
7. 规范化、去重、筛选并排序。
8. 冻结指向下一期的规律运行和全部合格信号。

运行ID固定为：

`sha256(game + targetIssue + windowDataHash + patternEngineVersion)`

重复定时任务、人工补跑或网络重试必须命中同一个运行ID。若结算成功但新扫描失败，旧复盘仍保留；不得把上一目标期的信号显示为下一期结果。

## 数据记录与接口

新增三个持久化实体：

- `rolling_pattern_runs`：运行ID、彩种、来源期、目标期、窗口首尾期、数据哈希、生成数、触发数、去重数、合格数、状态、冻结时间和引擎版本。
- `rolling_pattern_signals`：规则ID、运行ID、规则家族、目标事件、触发条件、历史触发与命中、原始概率、基准、原始提升、收缩概率、样本标签、相关规则数和排序分数。
- `rolling_pattern_scores`：规则ID、目标期、实际是否命中、实际分类结果和结算时间。

只读接口：

- `GET /api/research/patterns?game=<game>`：读取该彩种当前目标期冻结的运行及分页信号。
- `GET /api/research/patterns?game=<game>&issue=<issue>`：读取历史冻结运行和已结算结果。

写入沿用现有内部逐期学习任务的HMAC、时间窗口与幂等保护，不新增一套相互竞争的开奖定时器。

## 页面设计

新增 `/research/patterns`，移动端优先。研究导航统一为：

`高概率策略｜近30期规律｜逐期复盘`

页面从上到下包括：

1. **运行上下文**：彩种、目标期、最新30期范围、数据质量、冻结时间和引擎版本。
2. **扫描漏斗**：生成、当前触发、去重后、高于基准、最终展示数量。所有数字可核对，帮助发现漏扫或重复。
3. **分类筛选**：全部、生肖、尾数、波色、头数；默认只显示全部合格结果。
4. **规律卡片**：用自然语言说明触发条件和下一期事件；显示 `命中/触发`、原始命中率、随机基准、提升、收缩后概率、样本标签及最近30期状态条。
5. **展开审计**：展示每一次历史触发对应的来源期、预测目标期、命中结果，以及当前为何触发。
6. **空状态**：明确写明“本期没有同时满足当前触发和高于基准的近期规律”，不补充未触发结果。

卡片示例：

> 最近连续3期6+1未出现猪，本规则研究下一期6+1出现猪。近30期历史触发3次，命中2次，原始命中率66.7%；精确随机基准47.2%，高19.5个百分点；收缩后约52.5%，小样本，待验证。

页面不显示具体号码、投注建议、确定性语气或中奖承诺。

## 异常处理

- 最新一期来源冲突：停止结算和新扫描，页面显示“等待核验”。
- 合格数据少于30期：显示缺少的期数，不使用未核验数据补齐。
- 扫描任务失败：保留历史运行供复盘，但当前页显示“本目标期尚无冻结结果”。
- 没有合格规律：生成成功的空运行，合格数为0。空结果也是有效结果，不能反复重跑直到出现规律。
- 数据修订：产生新的数据哈希和新运行记录，旧运行保留并标注被修订，不覆盖旧结算。

## 验收测试

- 第31期加入后只保留最新30期，并验证最旧一期确实移除。
- 当前未触发但历史表现好的规律不得展示。
- `3次触发、2次命中` 且提升超过5个百分点的规律能够展示并标记“小样本”。
- 原始命中率等于或低于精确基准的规律不得展示。
- 生肖跨年映射、4/5号码尾数、三种波色和五个头数的组合基准计算正确。
- 规律历史评估不能读取目标期开奖或任何未来数据。
- 等价规则生成同一稳定ID，同一期重复扫描不产生重复记录。
- 开奖后先结算旧信号，再生成新的30期信号。
- 空结果会冻结并稳定恢复，刷新页面不会触发重新计算。
- 来源冲突、任务失败和数据修订均不会把旧目标期结果冒充为当前结果。
- 360像素宽页面无横向滚动，卡片数据和审计明细可读。
- 现有高概率策略、逐期复盘和历史冻结账本不发生回归。

## 发布边界

本次只增加独立的近30期规律发现、冻结与复盘能力，并补充研究导航。它不改变正式策略选择器、不把近期规律写入正式概率、不重算既有预测，也不承诺近期小样本规律能够提高长期中奖率。
