# 高概率策略中心：特码单双与大小固定槽位设计

## 目标

`/research` 每期继续冻结四个可结算方向，但将后两项从“任意指定位置的单双/大小”更改为固定的“特码单双”和“特码大小”。页面不再隐藏未达正式晋级门槛的方向；每张卡片都给出一个本期验证方向，同时保留“待验证”与“已验证”的证据边界。

## 固定四项

1. `6+1生肖覆盖`：保持现有候选和结算定义。
2. `6+1尾数覆盖`：保持现有候选和结算定义。
3. `特码单双`：只能在“特码单”和“特码双”中选一项。奇数为单，偶数为双。
4. `特码大小`：只能在“特码大”和“特码小”中选一项。1–24 为小，25–49 为大。

后两个槽位不再生成六个正码位置的候选，也不允许从正码位置候选中选择。

## 验证方向展示

四张卡片的主标题始终显示已冻结的 `predictionLabel`，不再使用“正式层暂无已验证方向”覆盖它。

- 达到正式门槛：标记为“正式验证方向”，继续使用正式概率。
- 有研究候选但未晋级：标记为“本期验证方向·研究候选”，展示校准候选概率，不声称已证明优势。
- 模型未超过基线：仍标记为“本期验证方向·基线记录”，保存被选方向以供开奖后客观结算，并明确说明尚未证明优势。

“给出方向”只改变展示和前瞻记录的完整性，不把未验证结果伪装成正式优势。

## 版本与历史兼容

新语义使用新槽位身份 `special_parity` 和 `special_size`，同时升级研究引擎、模型和复盘版本。旧槽位 `position_parity` 和 `position_size` 仅用于读取已有冻结快照和历史复盘。

兼容规则：

- 旧快照、结算、复盘和模型记录保留，不删除、不改写。
- 旧槽位的前瞻命中与权重不进入新特码槽位的在线学习。
- 新特码槽位可使用开奖历史进行滚动回测，但其独立前瞻结算样本从新版冻结开始计数。
- 同一目标期如果已有旧版冻结，新版只能通过新引擎身份追加一份快照，不能覆盖旧记录。
- 只有在开奖前成功冻结的新版快照才能进入正式结算；如果已过截止时间，新语义从下一期开始。

## 数据流与结算

1. 引擎为四个当前槽位生成候选。
2. 每个槽位按现有“校准绝对概率”目标选出一个方向。
3. 快照在开奖前写入不可变账本，页面只读取冻结结果。
4. 开奖后，生肖和尾数继续用 6+1 号码结算；新单双和大小只读取 `draw.special`。
5. 结算后记录命中、Brier、log-loss、基线对比和规则状态，仅更新对应新槽位的学习状态。

特码单双的精确基线为当年 01–49 号码中该类别所占比例（单 25/49，双 24/49）。特码大小的精确基线为大 25/49、小 24/49。

## 页面与文案

`/research` 的四项标签为：

1. 6+1生肖覆盖
2. 6+1尾数覆盖
3. 特码单双
4. 特码大小

第3、4项的范围文案固定为“特码”。页面说明同步改为“6+1生肖、6+1尾数、特码单双、特码大小”，不再使用“指定位置”。

`/research/review` 必须同时能正确显示旧位置槽位和新特码槽位，并按各自冻结语义结算。

## 失败与边界处理

- 数据不足或模型未晋级时，仍冻结一个验证方向，但显示未验证警示。
- 未核验开奖不结算。
- 过了开奖截止时间不补写当期新版冻结。
- 如果持久化或读取不可用，公开页面继续失败关闭，不在客户端重新生成方向。
- 旧数据解析失败不能降级为新槽位或零样本。

## 验证方案

- 候选集测试：`special_parity` 只有特码单/双，`special_size` 只有特码大/小。
- 边界测试：1、23为小，24为小，25为大，49为大；奇数为单，偶数为双。
- 结算测试：后两项只因特码改变，正码不得影响命中。
- 方向测试：正式、研究候选和基线记录三种状态都显示具体 `predictionLabel`。
- 隔离测试：旧 `position_*` 结算不会更新新 `special_*` 权重。
- 兼容测试：旧快照和旧复盘仍可读取、显示和审计。
- 接口与页面测试：预测 API 返回四个正确槽位，服务端渲染和客户端文案不再出现旧“指定位置”作为当前预测。
- 全量回归：类型检查、核心测试、研究流程测试、生产构建、部署检查和渲染/API 测试全部通过后才能发布。

## 不在本次范围

- 不改变 6+1 生肖和尾数的选择逻辑。
- 不预测 01–49 精确号码。
- 不删除旧位置预测历史。
- 不通过当期开奖结果反向选择或改写当期方向。
